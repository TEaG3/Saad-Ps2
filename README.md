# Saad PS2 Artwork Station

أداة عربية (RTL) لفحص ألعاب **PlayStation 2** الموجودة على فلاش USB، والتعرّف على أكوادها من داخل ملفات ISO نفسها
(`SYSTEM.CNF`) ومن `ul.cfg`، ثم جلب الأغلفة والأيقونات وحفظها بالمقاسات التي يحتاجها **OPL**:

| الملف | المقاس | الصيغة | المجلد |
|---|---|---|---|
| غلاف اللعبة | 140 × 200 | JPEG | `ART/` |
| أيقونة القرص | 64 × 64 | PNG | `ICONS/` |

التطبيق يعمل كـ **PWA** على الحاسوب/المتصفح، وكـ **تطبيق Android** مبني على Capacitor مع إضافة أصلية للوصول إلى
التخزين عبر Storage Access Framework (SAF). كل المعالجة تجري على الجهاز، ولا تُرفع ملفات الألعاب أو الصور إلى أي خادم.

---

## المزايا

- **فحص تلقائي**: يقرأ `DVD/` و`CD/` و`ul.cfg` من جذر الفلاش ويستخرج كود اللعبة من القطاع 16 داخل ISO.
- **مصدران للصور**: أونلاين (`xlenore/ps2-covers` للحفظ، وGameTDB للمعاينة كبديل) أو مجلد صور محلي للعمل دون اتصال.
- **معاينة قبل الكتابة**: الفحص لا يعدّل أي ملف؛ الحفظ يبدأ بأمر المستخدم فقط.
- **تحقق من الحفظ**: كل صورة تُقرأ مرة ثانية ويُقارن محتواها بالبايت قبل اعتبارها ناجحة (مع 3 محاولات).
- **مكتبة قابلة للبحث والتصفية**: معرض أو قائمة، تصفية حسب النقص/الصيغة، ترتيب، وتحديد جماعي للمزامنة.
- **قاعدة بيانات محلية**: IndexedDB لمكتبتك + كتالوج مركزي قابل للتحديث، مع تصدير/استيراد نسخة احتياطية JSON.
- **تصدير CSV** لقائمة الألعاب الظاهرة.
- **PWA**: تثبيت، عمل دون اتصال، وتنبيه عند توفر تحديث للواجهة أو للتطبيق.
- **إصلاحات وأمان**: تحرير ذاكرة المعاينات، سياسة CSP، تحقق من حجم/نوع الصور اليدوية، وتنبيهات غير معطِّلة بدل `alert`.

## التشغيل محليًا

```bash
# أي خادم ثابت يعمل؛ Service Worker يحتاج http/https وليس file://
npx http-server . -p 8080 -c-1
# ثم افتح http://127.0.0.1:8080
```

فحص المجلدات مباشرة يحتاج **Chrome أو Edge** على الحاسوب (File System Access API)، أو تطبيق Android.

## بناء تطبيق Android

البناء يتم عبر GitHub Actions: `.github/workflows/android-apk.yml`

1. Actions ← **Build Saad PS2 Android APK** ← Run workflow.
2. نزّل `saad-ps2-android-apks` من مخرجات البناء، أو افتح صفحة [إصدارات Android](https://github.com/TEaG3/Saad-Ps2/releases/tag/android-latest).
3. يتوفر `app-debug.apk` و`app-release.apk`. نسخة Release موقعة بمفتاح debug مؤقت للتثبيت الجانبي، وليست توقيع متجر ولا تضمن تحديثاً سلساً فوق إصدار موقّع بمفتاح مختلف.

ينسخ الـ workflow الأصول التالية إلى `www/` قبل `cap sync`:
`index.html`، `styles.css`، `app.js`، `manifest.webmanifest`، `sw.js`، `icon.svg`،
`saf-storage-bridge.bundle.js` (يُبنى من `android-native/`)، `game-database.js`، و`database/`.

## بنية المشروع

```
index.html                      الواجهة (RTL، بدون منطق مضمّن)
styles.css                      نظام تصميم + استجابة + مظهر داكن/فاتح
app.js                          منطق التطبيق (IIFE، بلا اعتماديات خارجية)
game-database.js                IndexedDB: الفحص، الكتالوج، التصدير/الاستيراد
sw.js                           Service Worker (Network-first للصفحة، Cache-first للأصول)
manifest.webmanifest            بيانات PWA
icon.svg                        الأيقونة
database/                       الكتالوج المركزي (manifest.json + catalog.json)
android-native/                 MainActivity + إضافة SAF + جسر esbuild
.github/workflows/              بناء APK
_archive/                       نسخ قديمة من ملفات workflow (غير مستخدمة)
```

## ملاحظات تقنية

- **الخصوصية**: لا يوجد أي `fetch` يرفع بيانات المستخدم؛ الطلبات الصادرة هي فقط لجلب الأغلفة وملف الإصدار.
- **CSP**: `default-src 'self'`، `object-src 'none'`، `base-uri 'none'`، وتُسمح الصور من `https:` فقط.
- **GameTDB**: لا يرسل `Access-Control-Allow-Origin`، لذا يُستخدم للمعاينة كـ `<img>` فقط ولا يدخل في مسار التنزيل/الحفظ.
- **الأداء**: معاينة كسولة عبر `IntersectionObserver`، تخزين مؤقت لروابط الصور (`blob:`) وتحريرها عند إعادة الفحص،
  وتحديث بطاقة واحدة بعد كل عملية بدل إعادة رسم القائمة.
- **التوافق**: يُفضّل إبقاء «العمليات المتوازية» على 1 مع USB OTG لتقليل أخطاء الكتابة.
